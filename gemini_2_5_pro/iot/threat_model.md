| Threat Type | Scenario | Potential Impact |
|-------------|----------|------------------|
| Spoofing | An attacker on the same 'public access LAN' as the IoT Edge device could impersonate the M1 module. By using techniques like ARP spoofing, the attacker can intercept the initial connection from the user's browser, presenting a fake web application to steal credentials or inject malicious scripts. | Theft of user credentials (if login is part of the webapp), manipulation of the user's view of the system, or launching client-side attacks against the user's browser. |
| Spoofing | An attacker on the 'public access LAN' can send crafted WebSocket messages to M2 or M3, pretending to be a legitimate upstream module (e.g., spoofing M1 to M2). This could be used to inject malicious or fabricated data into the processing pipeline. | Generation of incorrect audio output, pollution of debug data in Azure Storage, or triggering unintended actions in downstream modules. |
| Spoofing | An attacker on the IoT Edge device's network path to the internet could use DNS spoofing to redirect requests for Azure Cognitive Services to a malicious server. The malicious server could then capture the connection string from the request headers. | Loss of the Cognitive Service connection string, allowing the attacker to make unauthorized API calls, leading to financial cost and data leakage. |
| Tampering | Since modules communicate via WebSockets on a public access LAN, an attacker can perform a Man-in-the-Middle (MITM) attack to intercept and alter the data flowing between M1, M2, and M3. For example, they could modify the video frames in transit. | The system processes altered data, leading to incorrect OCR and Text-to-Speech results. Confidential information in the video could be replaced or manipulated. |
| Tampering | An attacker with access to the IoT Edge device's local storage could modify the container images for M1, M2, or M3 that were deployed by the CI/CD pipeline. The next time the module starts, it will run the attacker's tampered code. | Complete compromise of the module's functionality, data exfiltration, or using the module as a pivot point to attack other systems. |
| Tampering | An attacker who has obtained the connection string for the Azure Storage account can directly connect to it and modify or delete the 'feedback frames' uploaded by M2 for debugging purposes. | Loss of critical debugging data, preventing developers from diagnosing issues. Malicious data could be planted to mislead developers or hide evidence of an attack. |
| Repudiation | The system sends telemetry to Application Insights. An attacker who has compromised a module on the device could stop it from sending telemetry before performing malicious actions, leaving no trace in the logs. | The attacker's actions go undetected. The operations team is unable to prove that a specific device was compromised or that a malicious action occurred, hindering incident response. |
| Repudiation | An attacker or malicious user can submit a video stream for processing that triggers an undesirable outcome. Without strong, verifiable audit logs tying the browser session (via SSO identity) to the specific requests made to M1 and subsequent module interactions, the user could plausibly deny they submitted the content. | Inability to hold users accountable for their actions, which is critical if the system processes sensitive or regulated content. |
| Information Disclosure | The connection strings for Azure services are stored on the IoT Edge device to be used by the modules. An attacker who gains even low-privileged access to the device's filesystem or is able to read process environment variables could steal these connection strings. | Full access to the associated Azure Storage, Cognitive Service, and Application Insights instances, leading to massive data breaches and financial loss. |
| Information Disclosure | The WebSocket communication between M1, M2, and M3 on the 'public access LAN' may not be encrypted (i.e., using `ws://` instead of `wss://`). An attacker on the LAN can passively sniff this traffic and capture the raw video frames and OCR results. | Complete loss of confidentiality for all data processed by the system, including potentially sensitive visual information and text. |
| Information Disclosure | An attacker on the 'public access LAN' can directly connect to the HTTP endpoints of M1, M2, M3, and IoTEdgeMetricsCollector. If these endpoints have verbose error messages or unauthenticated status pages, they could leak internal system information, software versions, or data snippets. | Information leakage that aids an attacker in planning a more sophisticated attack, such as exploiting a known vulnerability in an exposed software version. |
| Denial of Service | An attacker on the 'public access LAN' can send a high volume of HTTP requests or initiate a large number of WebSocket connections to the M1 module. This would overwhelm its resources, preventing legitimate users from accessing the web application. | The system becomes unavailable to all users, causing a complete disruption of service. |
| Denial of Service | An attacker who has stolen an Azure connection string (e.g., for Cognitive Services) can run a script to make an unlimited number of API calls. This will rapidly consume the service's monthly quota or incur a very large bill. | Legitimate requests from the IoT device will be throttled or blocked, and the service owner will face a significant financial impact. |
| Denial of Service | An attacker with physical access to the IoT Edge device could simply disconnect the USB Video Camera, or an attacker with root access on the device OS could disable the USB port, cutting off the data source for the entire application. | The system is rendered completely non-functional as it can no longer receive the video input it is designed to process. |
| Elevation of Privilege | A vulnerability, such as a buffer overflow or command injection flaw, in the M1 module's HTTP endpoint could be exploited by an attacker on the 'public access LAN'. A successful exploit could lead to remote code execution within the M1 container. | An attacker gains a foothold on the IoT Edge device, can steal connection strings stored in the module's environment, and can attack other modules (M2, M3) from a trusted position. |
| Elevation of Privilege | An attacker who has achieved code execution inside a module container (e.g., M1) can attempt a 'container escape' attack. If the container is not properly isolated (e.g., running as root, having excessive kernel capabilities), the attacker could break out and gain root access to the host IoT Edge device OS. | Complete compromise of the IoT Edge device, its data, and all module secrets. The device could be used as a bot in a larger attack. |
| Elevation of Privilege | An attacker compromises the IoT Edge device and steals the Azure Storage connection string. This string grants them high-level permissions on the storage account itself. This elevates their privilege from control of a single edge device to control of a shared cloud resource. | The attacker can read, modify, or delete all data in the storage account, not just the data related to this specific device, potentially impacting other applications and systems. |
