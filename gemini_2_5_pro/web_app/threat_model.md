| Threat Type | Scenario | Potential Impact |
|-------------|----------|------------------|
| Spoofing | An attacker intercepts a user's session ID after they log in. Since the Web Service uses this ID for session management, the attacker can replay this ID to the Web Service to gain access as the legitimate user. | The attacker can access and manipulate the victim's customer data, including PII, leading to data theft and unauthorized actions performed on behalf of the user. |
| Spoofing | An attacker creates a phishing website that perfectly mimics the Web UI. A user is tricked into entering their username and password, which the attacker captures and uses to log into the real application. | Full account compromise, leading to the theft of all customer data and PII associated with that user account. |
| Spoofing | If the Web Service's XML parser is misconfigured to trust external entities and the Web UI-to-Web Service connection is not properly secured, an attacker could spoof internal server requests (Server-Side Request Forgery - SSRF) via a malicious XML payload. | The attacker could map the internal network of the Public Cloud trust zone, interact with internal-only services, or exfiltrate data from other systems within the AWS environment. |
| Tampering | An attacker injects a malicious XML payload into a request sent to the Web Service. The payload is crafted as an XML External Entity (XXE) injection, designed to alter data or execute unauthorized commands on the underlying EC2 instance. | Data corruption, unauthorized modification of customer PII in the PostgreSQL database, or execution of arbitrary code on the Web Service host. |
| Tampering | A malicious user manipulates data within their client-side session (e.g., in hidden form fields or parameters in a JQuery-driven request) to reference another user's ID or resources before submitting it to the Web Service. | If the Web Service lacks proper server-side authorization checks, the attacker could modify or delete another user's customer data, leading to data integrity violations. |
| Tampering | An attacker with access to the EC2 instance hosting the Web Service tampers with the application's configuration files to alter the database connection string, pointing it to a malicious database to skim data or changing application logic. | Interception and theft of PII, redirection of traffic, or complete loss of data integrity for all users. |
| Repudiation | A legitimate user modifies sensitive customer PII through the Web UI and later denies making the change. The system lacks detailed, immutable audit logs connecting the user's session ID to the specific database transaction. | The organization cannot prove who was responsible for a malicious or erroneous data modification, leading to unresolved disputes, failed compliance, and an inability to trace data breaches. |
| Repudiation | An attacker uses a compromised account to exfiltrate data. Due to insufficient logging of data access patterns (e.g., which records were viewed, by whom, and when), the organization cannot prove what specific data was stolen. | Inability to determine the scope of a data breach, preventing proper notification to affected customers and regulators, and incurring significant legal and financial penalties. |
| Information Disclosure | An attacker exploits an XML External Entity (XXE) vulnerability in the Web Service's XML parser to read sensitive files from the EC2 instance's file system, such as application configuration files containing PostgreSQL database credentials. | Theft of database credentials, allowing the attacker to connect directly to the RDS instance and exfiltrate all customer PII from the data store. |
| Information Disclosure | The Java Web Service returns a detailed stack trace in an error message to the client. This error reveals the specific version of the Java container, internal file paths, and database schema information. | An attacker gains valuable reconnaissance information, making it easier to craft more targeted attacks against known vulnerabilities in the revealed software components. |
| Information Disclosure | A user's session ID is passed in the URL. This ID is leaked to third parties via the Referer header when the user clicks an external link, or is stored in browser history, proxy logs, or server logs. | Exposure of the session ID allows an attacker to hijack the user's session and gain unauthorized access to their PII. |
| Denial of Service | An attacker sends a specially crafted XML document, known as an 'XML Bomb' or 'Billion Laughs Attack', to the Web Service. The parser attempts to process the nested entities, consuming all available CPU and memory on the EC2 instance. | The Web Service becomes unresponsive and crashes, making the entire application unavailable to all legitimate users. |
| Denial of Service | An attacker initiates a large number of concurrent connections and sessions with the Web Service. If session lifecycle and resource pooling are not properly managed, the service exhausts available memory or database connections. | The application becomes slow or completely unavailable for legitimate users due to resource exhaustion on the EC2 instance or the RDS database. |
| Denial of Service | An attacker repeatedly submits requests for a computationally expensive operation via the Web UI (e.g., a complex search or report generation), causing the Web Service and PostgreSQL database to be overloaded. | Degradation of service for all users as the database CPU is consumed, potentially leading to timeouts and a complete outage. |
| Elevation of Privilege | A low-privilege user finds a Cross-Site Scripting (XSS) vulnerability in the JQuery Web UI. They craft a malicious link and send it to an administrator. When the administrator clicks it, the injected script steals their session ID, allowing the attacker to hijack the admin's session. | The attacker gains full administrative privileges, allowing them to access/modify all customer data, change system settings, or create/delete user accounts. |
| Elevation of Privilege | The Web Service connects to the PostgreSQL database using an account with excessive permissions (e.g., 'postgres' superuser). An attacker who compromises the Web Service through a vulnerability like XXE can now use these credentials to perform administrative actions on the database, such as creating new users or disabling security controls. | Complete compromise of the database server, escalating a breach of the application layer to a breach of the data layer with persistent access. |
| Elevation of Privilege | An authenticated user discovers that API endpoints on the Web Service do not perform authorization checks to verify that the user is the owner of the data they are requesting. The user modifies an API request to include another user's ID, successfully accessing their data. | A standard user can elevate their privileges horizontally to access and modify any other user's PII, leading to a widespread data breach. |
