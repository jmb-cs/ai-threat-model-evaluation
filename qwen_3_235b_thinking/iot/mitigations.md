

| Threat Type          | Scenario                                                                                                                                 | Suggested Mitigation(s)                                                                                                                                                                                                                                                                                                                               |
|----------------------|------------------------------------------------------------------------------------------------------------------------------------------|-------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Spoofing             | An attacker spoofs the identity of the USB Video Camera to send malicious video frames to M3, which then get processed by downstream modules as legitimate input | • Enforce USB device authorization via Linux kernel-level whitelisting (e.g., `usbguard` rules based on VID/PID)<br>• Implement frame-level cryptographic signing at the camera firmware level (if hardware supports it) with keys stored in TPM<br>• Validate frame integrity in M3 using hash-based message authentication codes (HMAC) with rotating keys |
| Spoofing             | An attacker spoofs the identity of M1 to intercept browser requests on the local LAN, conducting a man-in-the-middle attack against legitimate user sessions | • Implement mutual TLS (mTLS) for all browser-M1 communications with client certificates pinned to device identities<br>• Configure strict DNSSEC validation for local LAN resolution<br>• Enforce HTTP Strict Transport Security (HSTS) with `max-age=31536000` and includeSubDomains directive |
| Spoofing             | An attacker spoofs Azure Cognitive Services endpoint to intercept OCR and Text-to-Speech requests from M3                                | • Use Azure Private Link for Cognitive Services to keep traffic within Azure backbone<br>• Implement certificate pinning in M3 against Azure's root CA certificates<br>• Validate endpoint certificates using `X509Chain.Build()` with explicit trusted issuer constraints in .NET code |
| Tampering            | An attacker intercepts and modifies WebSocket communications between M1, M2, and M3 on the local network                                   | • Enforce WebSocket Secure (wss://) with TLS 1.3 and require mutual authentication between modules<br>• Apply per-message authenticity via HMAC-SHA256 using ephemeral keys rotated hourly<br>• Segment module communications via VLANs with 802.1X port security |
| Tampering            | An attacker tampers with telemetry data being sent from EdgeMetricsCollector to Application Insights by injecting falsified data         | • Digitally sign telemetry payloads using ECDSA keys stored in Azure IoT Edge Device Provisioning Service<br>• Implement schema validation at ingestion point via Azure Event Grid filters<br>• Configure Application Insights ingestion-time sampling with anomaly detection thresholds |
| Tampering            | An attacker tampers with video frames stored in Azure Storage that were uploaded by M2 for debugging purposes                            | • Enable Azure Blob Immutable Storage with legal hold policies for debug containers<br>• Calculate and store SHA-256 hashes of original frames in Azure Key Vault<br>• Configure storage accounts with blob versioning and container-level WORM retention policies |
| Repudiation          | A malicious insider alters or deletes telemetry data sent to Application Insights after performing unauthorized actions on the system | • Implement write-once-read-many (WORM) compliance via Azure Storage Time-Based Retention Policies<br>• Deploy dual-write architecture sending copies to isolated SIEM system<br>• Enable Azure Monitor diagnostic settings with direct streaming to Log Analytics workspace |
| Repudiation          | An attacker who gained access to M1 performs unauthorized operations via browser interface but the system lacks sufficient transaction logging | • Instrument all user actions with Azure Application Insights custom events including client IP, device fingerprint, and module context<br>• Configure Azure IoT Edge Runtime audit logs with 180-day retention in secured Log Analytics workspace<br>• Implement session recording via Azure Video Analyzer for critical operations |
| Repudiation          | An external attacker tampers with logs sent to Azure Monitor by modifying timestamps or content during transmission                       | • Encrypt logs in transit using TLS 1.3 with mutual authentication<br>• Apply log integrity validation via Azure Monitor's Content Hash verification<br>• Configure Azure Log Analytics agent with `-UseCompression` and `-UseSharedKeyAuthentication` for payload integrity |
| Information Disclosure | Connection strings for Azure services are exposed through insecure GitHub secrets management or CI/CD pipeline artifacts                 | • Replace all connection strings with Azure Managed Identities for module authentication<br>• Integrate GitHub Actions with Azure Key Vault via OIDC federation<br>• Implement pre-commit hooks scanning for Azure secrets using Trufflehog |
| Information Disclosure | Debugging video frames uploaded to Azure Storage contain personally identifiable information from camera feeds                           | • Deploy automatic PII redaction in M2 using Azure Video Analyzer for Media prior to upload<br>• Configure Azure Storage container with double encryption (Microsoft-managed + customer-managed keys)<br>• Implement Azure Policy to block PII-containing blobs via Content Moderation API integration |
| Information Disclosure | WebSocket communications between M1, M2, and M3 lack encryption on the local network                                                     | • Enforce mandatory TLS 1.3 for all inter-module communications using Azure IoT Edge routing<br>• Configure network-level IPSec tunnels between edge device modules<br>• Implement WebSocket subprotocol negotiation requiring `permessage-deflate` compression |
| Denial of Service    | An attacker floods M1's HTTP endpoint with excessive requests from the browser interface                                                 | • Deploy Azure Front Door with WAF rate limiting (5 requests/sec per client IP)<br>• Configure IoT Edge `minReplicas=2` with automatic scaling based on CPU thresholds<br>• Implement request funneling via Azure API Management with JWT validation |
| Denial of Service    | An attacker sends specially crafted video frames via the USB Camera interface that cause resource exhaustion in M3 processing              | • Enforce frame size/resolution limits in M3 (e.g., max 1080p at 30fps)<br>• Implement sandboxed frame processing using container resource constraints (CPU/memory limits)<br>• Deploy runtime anomaly detection via Azure Security Center's container monitoring |
| Denial of Service    | An attacker floods Azure Cognitive Services with excessive requests through M3 by manipulating the edge device                            | • Configure Cognitive Services resource with strict quota limits (requests/minute)<br>• Implement request queuing with exponential backoff in M3<br>• Deploy Azure API Management policies with client-throttling based on Edge device identity |
| Elevation of Privilege | An attacker exploits vulnerabilities in M1 to gain shell access to the IoT Edge device and then escalate privileges to control EdgeRuntime | • Harden OS via CIS benchmarks for Azure IoT Edge Linux devices<br>• Run modules in gMSA (Group Managed Service Accounts) with least privilege<br>• Enable runtime protection via Falco with custom rules for edge module privilege escalation |
| Elevation of Privilege | A compromised IoT Edge module accesses connection strings from memory and uses them to gain administrative access to Azure services       | • Replace connection strings with Azure Managed Identities for all Azure service access<br>• Implement memory encryption via Intel SGX enclaves for credential handling<br>• Configure Azure Policy to block non-identity-based access to resources |
| Elevation of Privilege | An attacker gains access to GitHub secrets containing Azure connection strings through a supply chain attack on CI/CD pipelines            | • Enforce just-in-time access to secrets via Azure Key Vault with short-lived SAS tokens<br>• Implement GitHub environment protection rules requiring 2-person approval for secret changes<br>• Conduct real-time secret scanning using Azure Defender for Cloud's repositories protection |
