| Threat Type | Scenario | Potential Impact |
|-------------|----------|------------------|
| Spoofing | An attacker on the same LAN as the IoT Edge device and Browser captures or reuses SSO authentication artifacts (e.g., tokens, cookies) from a user’s Browser session to M1’s HTTP endpoint, then sends their own requests to M1 pretending to be that user. | Unauthorized access to live video streams and order scanning results; ability to trigger OCR/Text-to-Speech operations and potentially exfiltrate confidential content under another user’s identity. |
| Spoofing | A malicious process on the IoT Edge device or another device on the LAN impersonates M2 or M3 by opening a WebSocket endpoint that M1 connects to, if module-to-module authentication is not enforced on the WebSocket channels. | Injection of fabricated video frames, order data, or scan results to M1, leading to incorrect application behavior and possible downstream data corruption in Azure Storage and Cognitive Service outputs. |
| Spoofing | An attacker able to influence DNS resolution or host configuration on the IoT Edge device redirects the Azure Cognitive Service hostname to an attacker-controlled HTTP endpoint that mimics the real API. | Attacker receives all OCR and Text-to-Speech requests, gaining access to confidential video-derived text and audio content, and can send forged responses back to the IoT modules. |
| Spoofing | A malicious actor obtains an IoT Edge module’s credentials or identity (e.g., via stolen deployment credentials or misconfigured IoT Hub identities) and registers a fake IoT Edge device or EdgeRuntime that appears legitimate to Azure IoT Hub. | Unauthorized device can receive configuration and secrets (connection strings) and send falsified telemetry to Application Insights, undermining trust in monitoring and potentially exposing sensitive configuration data. |
| Tampering | An attacker with access to the local network or compromised module intercepts and modifies WebSocket traffic between M1, M2, and M3 (if not protected with integrity mechanisms/TLS), altering video frames or order scanning results in transit. | Corrupted or manipulated visual and OCR data, leading to incorrect business decisions, mis-processed orders, or fraudulent outcomes based on forged scan results. |
| Tampering | An attacker with limited access to the IoT Edge device filesystem (e.g., via another low-privileged process) modifies configuration files or environment variables that contain Azure Storage, Cognitive Service, or Application Insights connection strings. | Modules may send data to attacker-controlled Azure resources, leak confidential data, or be prevented from sending data to the legitimate services; attacker also gains ability to act with the privileges of the modified connection strings. |
| Tampering | A malicious insider or compromised process alters the debug data or feedback frames that M2 uploads to Azure Storage (e.g., overwriting original frames with forged ones or corrupting stored blobs). | Debugging and forensic analyses become unreliable; operations teams may be misled about the root cause of issues or may miss evidence of other attacks, impairing incident response and system reliability. |
| Tampering | A malicious actor tampers with telemetry sent to Azure Application Insights or Azure Monitor (e.g., by altering metric values or log contents in the sending modules) to hide abnormal behavior or fabricate normal operation. | Security and operational monitoring becomes untrustworthy; attacks, performance issues, or data leaks may go undetected or be misdiagnosed, increasing dwell time and damage. |
| Repudiation | Because the Browser–M1 interaction details and audit logging are unclear, a user who initiated a set of OCR or Text-to-Speech requests later claims they never accessed certain confidential content, and there is insufficient linkage between SSO identity, session, and specific actions. | Difficulty proving who accessed or processed specific confidential video frames, complicating incident investigations, compliance reporting, and potential legal disputes. |
| Repudiation | An operator modifies IoT Edge module configurations (e.g., changes which Azure Storage account is used or toggles debug uploads) on the device, but the EdgeRuntime and modules do not log detailed, tamper-resistant configuration changes with identities and timestamps. | Configuration changes that led to data leakage or outages cannot be attributed to a specific person or time, impeding root-cause analysis and accountability. |
| Repudiation | Deployments and updates from Azure IoT Hub to the IoT Edge device occur without detailed, immutable audit records at both ends (Hub and device) linking configuration changes to specific administrative identities. | An administrator could deploy a malicious or misconfigured version of M1/M2/M3 and later deny having done so; it becomes challenging to prove which deployment introduced a vulnerability or outage. |
| Repudiation | Telemetry to Application Insights and Azure Monitor is sent without strong association to specific device identities and module versions, and logs are not protected against post-hoc modification. | Adversaries who compromise a module could alter or delete logs and then deny their actions; investigators cannot reliably reconstruct timelines or attribute actions to particular components. |
| Information Disclosure | Connection strings for Azure Cognitive Service, Storage, Application Insights, and Azure Monitor—deployed from GitHub secrets to the IoT Edge device—are stored in plain text on disk or in environment variables readable by other processes on the device. | Any process or attacker with access to the device can extract these secrets, gain direct access to Azure resources, read confidential debug frames or telemetry, and impersonate the application from other locations. |
| Information Disclosure | If WebSocket connections between M1, M2, and M3 on the public-access LAN are not encrypted, an attacker with LAN access can sniff network traffic and reconstruct live video frames, OCR text, and scan results as they traverse the network. | Exposure of confidential video content, order information, and potentially personal or sensitive data, leading to privacy violations and regulatory non-compliance. |
| Information Disclosure | Debug data and feedback frames uploaded by M2 to Azure Storage are stored in a container accessible using a high-privilege connection string; if the storage account or connection string is misconfigured (e.g., overly broad access or exposed in logs), external parties can list and download stored frames. | Large-scale leakage of historical video frames and associated data intended only for debugging, exposing long-term records of sensitive operational environments or individuals captured on camera. |
| Information Disclosure | Telemetry sent to Application Insights and Azure Monitor may include sensitive content (e.g., snippets of OCR results, partial video frame data, or identifiers) and is accessible to a broad set of Azure subscribers or administrators within the tenant without strict role separation. | Personnel who do not need access to raw or derived confidential data can view it via monitoring tools, increasing the insider threat surface and violating least-privilege principles for confidential information. |
| Denial of Service | An attacker on the local network sends a flood of HTTP requests to M1’s public-access LAN endpoint from multiple machines, exhausting CPU, memory, or network resources on the IoT Edge device. | Legitimate users lose access to live video streaming and order scanning functionality; the IoT Edge device may become unstable or unresponsive, disrupting business operations relying on real-time processing. |
| Denial of Service | A malicious or compromised Browser repeatedly triggers intensive OCR and Text-to-Speech requests via M1/M2/M3 to Azure Cognitive Service, intentionally driving the service beyond its rate or quota limits. | Azure Cognitive Service throttles or rejects further requests, halting legitimate OCR and audio processing and potentially degrading service for other applications sharing the same Cognitive Service instance. |
| Denial of Service | A bug or malicious logic in M2 causes massive uploads of feedback frames to Azure Storage (e.g., an infinite loop writing large blobs), exhausting storage capacity or hitting request-rate limits. | Storage operations required for legitimate debugging and possibly other applications are disrupted; added costs and inability to store new diagnostic data hamper troubleshooting and system reliability. |
| Denial of Service | An attacker who gains partial control over IoT Hub configuration sends frequent, large deployment updates or restarts to the IoT Edge device’s modules (M1, M2, M3, EdgeRuntime), forcing constant restarts. | Continuous service flapping on the IoT Edge device prevents processing of video frames and telemetry; the device becomes effectively unusable for its intended IoT workloads. |
| Elevation of Privilege | A vulnerability in one of the IoT Edge modules (e.g., M1’s web application) allows remote code execution inside its container, and container or host runtime is misconfigured such that the attacker can access host resources and other module containers. | Attacker moves from controlling a single module to controlling the entire IoT Edge device, gaining access to all secrets, video data, and the ability to manipulate interactions with Azure services and IoT Hub. |
| Elevation of Privilege | An attacker who obtains a high-privilege Azure Storage connection string from the Edge device uses it from an external environment to perform administrative operations on the storage account (e.g., create SAS tokens, modify access policies). | Attacker escalates from being able to read a subset of debug frames to fully administering the storage account, potentially granting broader access to additional containers or applications and enabling large-scale data exfiltration or tampering. |
| Elevation of Privilege | SSO integration to M1 does not enforce fine-grained roles, and all authenticated users are treated as having administrative capabilities (e.g., triggering configuration changes, debugging modes, or forcing uploads to Azure Storage). | A normal user account becomes effectively an administrator, able to alter how and where data is processed, increase logging of sensitive data, or turn on debug uploads that expose more confidential frames to Azure Storage and monitoring systems. |
| Elevation of Privilege | Inter-module communication on the IoT Edge device is not isolated by least-privilege rules, allowing a compromised low-privilege module (e.g., the Metrics Collector) to directly invoke privileged operations on M2/M3 or EdgeRuntime APIs. | An initially low-impact compromise of a metrics or auxiliary module escalates into full control over the video processing pipeline and EdgeRuntime, enabling alteration of workloads, exfiltration of secrets, and persistent backdoors. |
